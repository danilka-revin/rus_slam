Веб-панель управления роботом-курьером 4WIS/4WID в визуальном языке
**ZMK Vision**: тёмный сайдбар `#101b17`, акцент `#d5ff45`,
светлая рабочая зона `#f3f5f7`. В каталоге `gui/` лежат
`index.html`, `styles.css`, `app.js`, `vision.js`, `README.md` —
без сборщиков, без npm, без зависимостей.

---

## 1. Назначение

GUI — это **пульт оператора**, через который инженер-испытатель
управляет автономным роботом-курьером 4WIS/4WID и наблюдает его
состояние во время стендовых и полигонных испытаний, а также
при подготовке к соревнованиям НТЦ АВТОВАЗ
(Задание № 2 «Автономное роботизированное устройство для внутренней
логистики»).

### Что умеет пульт

* **Телеуправление** — клавиатура (`W/A/S/D/Q/E` + стрелки),
  виртуальный джойстик (drag мышью), экстренный стоп (`Space`).
* **Крабовый ход** — переключатель `crab` в верхней панели: при
  включении все 4 модуля поворачиваются синхронно, кнопки `A/D`
  дают боковое смещение без поворота корпуса.
* **Автономные сценарии** — автоскан (SLAM-объезд всего помещения),
  старт маршрута по точкам, программа доставки
  («А → загрузка → Б → выгрузка → база»), возврат на базу.
* **SLAM-карта** — отрисовка в реальном времени занятой/свободной/
  неизвестной области по лидарному скану, путь планировщика A*,
  путевые точки, площадки А/Б/база, сканирование мира.
* **Симулятор** — если робот не подключён, GUI крутит всю физику и
  сенсорику сам (лидар, камера, знаки, одометрия, FSM, e-stop).
  Это сделано для демонстрации, обучения операторов и отладки
  логики без реального железа.

### Чего пульт НЕ делает

* Не подключается к ROS 2 — это **самостоятельный симулятор**.
  Для интеграции с реальным ROS-стеком используйте
  `rosbridge_server` + кастомный мост (см. раздел 9).
* Не хранит данные на сервере — все маршруты и группы точек
  сохраняются в `localStorage` браузера.

## 4. Архитектура пульта

### 4.1 Глобальное состояние

Всё состояние хранится в одном объекте `state`, объявленном
в `app.js`. Ключевые поля:

| Поле | Тип | Назначение |
| :--- | :--- | :--- |
| `state.view` | `"dash" \| "drive" \| "mission" \| "sensors" \| "safety" \| "logs"` | Текущая вкладка |
| `state.estop` | `bool` | Состояние E-STOP |
| `state.crab` | `bool` | Режим крабового хода |
| `state.vmax` | `number` | Максимальная скорость (м/с), регулируется ползунком |
| `state.clearance` | `number` | Зазор до препятствий (м) для планировщика |
| `state.x`, `state.y`, `state.yaw` | `number` | Поза робота в мировой системе (м, рад) |
| `state.spdVx`, `state.spdVy`, `state.spdWz` | `number` | Реальные (после инерции) скорости |
| `state.bat`, `state.soc`, `state.current` | `number` | Батарея: В, %, А |
| `state.waypoints[]` | `[{x,y}]` | Список путевых точек |
| `state.navPath[]` | `[{x,y}]` | Текущий путь планировщика A* |
| `state.scan[]` | `[{a, r}]` | Лучи лидара (180 точек на 360°) |
| `state.modules[]` | `[{id, steer, rpm, temp, homed}]` | 4 модуля FL/FR/RL/RR |
| `state.mission` | `string` | Текущее состояние FSM |
| `state.program[]` | `string[]` | Очередь шагов программы доставки |

### 4.2 Конечный автомат (FSM)

```js
const FSM = ["IDLE", "READY", "NAVIGATE",
             "YIELD_SIGN", "WAIT_LIGHT",
             "DELIVER", "RETURN", "FAULT"];
```

Переходы (в коде `app.js`):

* `IDLE → READY` — оператор дал любую команду движения или нажал
  «Старт маршрута».
* `READY → NAVIGATE` — авто-режим: строится путь A*, робот едет
  к следующей waypoint.
* `NAVIGATE → YIELD_SIGN` — лидар/знак «СТОП» или «светофор»:
  скорость уменьшается, FSM ждёт подтверждения.
* `NAVIGATE → DELIVER` — робот доехал до площадки Б, идёт выгрузка.
* `DELIVER → RETURN` — после `confirmUnload()` едет на базу.
* `* → FAULT` — нажат E-STOP, модуль не отвечает, низкий SOC.
* `FAULT → IDLE` — снят E-STOP.

### 4.3 Кинематика 4WIS/4WID

Геометрия модулей (из `app.js`):

```js
const CHASSIS = [
  { id: "FL", x:  0.34, y:  0.22 },
  { id: "FR", x:  0.34, y: -0.22 },
  { id: "RL", x: -0.34, y:  0.22 },
  { id: "RR", x: -0.34, y: -0.22 },
];
```

Это расстояния от центра масс до точки контакта колеса с полом
(м). Функция `compute4WIS(vx, vy, wz)` раскладывает скорость по
колёсам и считает требуемые `steer` (рад) и `rpm` для каждого
модуля:

```js
for (const w of CHASSIS) {
  const vix = vx - wz * w.y;       // скорость точки колеса по X
  const viy = vy + wz * w.x;       // …по Y
  const spd = Math.hypot(vix, viy);
  let steer = Math.atan2(viy, vix);
  // нормализация угла в ±π/2
  if (steer > Math.PI / 2)  steer -= Math.PI;
  if (steer < -Math.PI / 2) steer += Math.PI;
  out.push({ id: w.id, x: w.x, y: w.y, steer, rpm: spd * 180 });
}
```

В **крабовом режиме** (`state.crab === true`) `wz` принудительно
обнуляется и `steer` для всех колёс становится одинаковым —
робот едет боком или по диагонали без поворота корпуса.

### 4.4 Главный цикл рендеринга

```js
function loop(now) {
  const dt = Math.min(0.05, (now - last) / 1000);
  try {
    applyKeys();      // клавиатура → vx/vy/wz
    publishCmd();     // обновить индикаторы команд
    sim(dt);          // физика: pose, modules, battery, scan
    drawStick();      // виртуальный джойстик
    drawMap();        // SLAM-карта (canvas)
    drawChassisPanel();// шасси сверху (canvas)
    drawCam(now);     // камера перед/зад (canvas, raycast)
    drawLidar();      // радар 360° (canvas)
  } catch (err) { console.error(err); }
  requestAnimationFrame(loop);
}
```

Кадры симуляции идут через `requestAnimationFrame` (~60 FPS),
телеметрия обновляется по факту изменения значений.

## 5. Управление

### 5.1 Клавиатура

| Клавиша | Действие |
| :---: | :--- |
| `W` / `↑` | Движение вперёд |
| `S` / `↓` | Движение назад |
| `A` / `←` | Поворот влево (или крабовый ход влево при включённом `crab`) |
| `D` / `→` | Поворот вправо (или крабовый ход вправо) |
| `Q` | Крабовый сдвиг `vy+` |
| `E` | Крабовый сдвиг `vy-` |
| `Space` | E-STOP (мгновенная остановка, обнуляет все скорости, снимает авто-режим) |
| `H` | Хоминг модулей (отправляет команду 4 модулям «обнулить азимут») |

Реализация в `app.js`:

```js
window.addEventListener("keydown", (e) => {
  if (!DRIVE_KEYS.has(e.code)) return;
  e.preventDefault();
  if (e.code === "Space") {
    state.vx = state.vy = state.wz = 0;
    state.keys = {};
    state.auto = false;
    state.explore = false;
    dragging = false;
    publishCmd();
    return;
  }
  if (e.code === "KeyH") { homeModules(); return; }
  state.keys[e.code] = true;
  applyKeys();
  publishCmd();
});
```

### 5.2 Виртуальный джойстик

Drag-мышью по холсту `<canvas id="stick">` — координаты пересчитываются
в `vx`, `vy`, `wz` с учётом `vmax` и `crab`:

```js
function stickFromEvent(ev) {
  const r = stick.getBoundingClientRect();
  const x = (ev.clientX - r.left) / r.width * 2 - 1;
  const y = (ev.clientY - r.top) / r.height * 2 - 1;
  state.vy = clamp(x) * state.vmax * (state.crab ? 1 : 0);
  state.vx = clamp(-y) * state.vmax;
  if (!state.crab) state.wz = clamp(-x) * state.vmax * 1.1;
}
```

### 5.3 Режимы работы

| Режим | Когда включается | Что делает |
| :--- | :--- | :--- |
| `TELEOP` | По умолчанию | Оператор управляет клавиатурой/джойстиком |
| `AUTO · маршрут` | Кнопка «Старт маршрута» | A* по точкам, автопроезд |
| `AUTO · сканирование` | Кнопка «Автоскан» | Робот ездит по frontier'ам, пока карта не покроется >62 % |
| `AUTO · программа` | Кнопка «Запустить мою программу» | Шаги из `state.program` (А→загрузка→Б→выгрузка→база) |
| `AUTO · на базу` | Кнопка «На базу» / SOC < 18 % | Доехать до dock-станции, начать зарядку |
| `E-STOP` | Кнопка E-STOP / `Space` | Гейт закрыт, скорости обнулены |

### 5.4 Программа доставки (список шагов)

Кнопки «Добавить шаг» добавляют в `state.program` записи:

| Кнопка | Запись | Описание |
| :--- | :--- | :--- |
| ＋ ехать на А | `goA` | Подъехать к площадке загрузки |
| ＋ ехать на Б | `goB` | Подъехать к площадке выгрузки |
| ＋ взять груз | `load` | Ожидание подтверждения загрузки |
| ＋ сдать груз | `unload` | Ожидание подтверждения выгрузки |
| ＋ по точкам | `goP` | Проехать по кликнутым точкам на карте |
| ＋ пауза 2 с | `wait` | Стоять 2 секунды |
| ＋ на базу | `dock` | Возврат на док-станцию |
| ＋ зарядиться | `charge` | Зарядка до `chargeTo %` |
| ＋ цикл | `loop` | Повтор с шага 1 |

После составления очереди нажмите «Запустить мою программу» — FSM
выполнит шаги сверху вниз, в нужных местах потребует ручного
подтверждения «груз взят» / «груз сдан».

## 6. SLAM и планирование пути

### 6.1 Лидар

180 лучей, развёрнутых на 360°, дальность 10 м. Каждый кадр:

```js
for (let i = 0; i < LIDAR_BEAMS; i++) {
  const a = state.yaw + (i / LIDAR_BEAMS) * Math.PI * 2;
  state.scan.push({ a, r: raycast(state.x, state.y, a, LIDAR_MAX) });
}
```

`raycast` бросает луч по сетке `WORLD.walls` и `WORLD.racks` и
возвращает расстояние до первого пересечения.

### 6.2 Occupancy grid

Сетка 320 × 240 ячеек, разрешение 0.12 м/яч, мировые координаты
от -18 до +18 м по X и от -12 до +12 м по Y. На каждом кадре
`integrateScan()` обновляет значения:

| Код | Цвет в vision.js | Значение |
| :---: | :---: | :--- |
| `UNK = 0` | `#151c19` (фон) | Неисследованная область |
| `FREE = 1` | `#3c433c` | Свободный проезд |
| `OCC = 2` | `#8a6a48` | Стена / стеллаж / препятствие |

Также строится `distGrid` — расстояние в метрах от каждой
свободной ячейки до ближайшего препятствия (двупроходный
Chamfer-distance, пересчитывается лениво при изменении карты).

### 6.3 Планировщик A*

Классический A* по 8-связной сетке с эвристикой Евклида и
учётом штрафа за близость к стенам (`wallCost`):

```js
function planPath(gx, gy) {
  /* 1. проверка целевой точки
     2. обычная очередь с приоритетом по f = g + h
     3. для каждого соседа: шаг = 1 (прямой) или 1.41 (диагональ)
        умножить на wallCost(nx, ny)
     4. восстановление пути через массив came[]                                    */
}
```

Параметр `clearance` (ползунок в UI, 0.5–1.5 м) задаёт
**минимальный зазор** до препятствий: если `wallCost` ячейки
выше порога, ячейка считается непроходимой (используется
инфляция препятствий `inflatedOcc`).

### 6.4 Карта и взаимодействие

* ЛКМ на карте — добавить точку маршрута (`state.waypoints.push`).
* ПКМ — убрать последнюю точку.
* Колесо мыши — зум (масштаб 8…50 px/м).
* Drag ЛКМ — панорамирование.
* Кнопка «К роботу» — центрировать камеру на текущей позе.
* Кнопка «Снимок карты» — PNG текущего вида (`canvas.toDataURL`).

## 8. Тема, маршруты, e-stop

### 8.1 Тема

Две темы — тёмная (по умолчанию, сайдбар `#101b17`, фон `#0b120f`)
и светлая (фон `#f3f5f7`). Выбор сохраняется в `localStorage`:

```js
const KEY = "rus_slam_theme";
applyTheme(localStorage.getItem(KEY) !== "light");
```

Переключение — кнопка «Тёмная/Светлая» в шапке.

### 8.2 Сохранённые группы точек

Пользовательские маршруты (`state.waypoints`) можно сохранять в
`localStorage` под именем. Структура хранения:

```js
const ROUTES_KEY = "rus_slam_route_groups";
// [{ name: "цех-А", points: [{x, y}, ...] }, ...]
```

Операции: «Сохранить группу», «Загрузить», «Удалить». Список
доступных групп подгружается в `<select id="route-list">`.

### 8.3 E-STOP

Кнопка `<button id="btn-estop">` в шапке переключает
`state.estop`. При включении:

* `state.vx = state.vy = state.wz = 0` (мгновенно).
* `state.auto = state.explore = false` (все авто-режимы прерваны).
* FSM → `FAULT`.
* Индикатор «Связь с базой» пульсирует красным.
* Кнопка подсвечивается красным, в журнал пишется
  `E-STOP asserted` уровня `err`.

Повторное нажатие снимает E-STOP и возвращает FSM в `IDLE`.

## 9. Интеграция с ROS 2 (опционально)

Текущий пульт — **самостоятельный симулятор** и не публикует данные
в ROS. Чтобы связать его с реальным роботом, нужны два слоя:

1. **`rosbridge_server`** на бортовом компьютере Ubuntu:

   ```bash
   sudo apt install -y ros-$ROS_DISTRO-rosbridge-server
   ros2 launch rosbridge_server rosbridge_websocket_launch.xml
   ```

2. **JS-мост** в `gui/app.js`, который публикует команды в `/cmd_vel_nav`
   и подписывается на `/odom`, `/battery_state`, `/module_status`,
   `/map` (см. `docs/SOFTWARE_ARCHITECTURE.md`).

Ниже — каркас, который можно вставить в `app.js` после объявления
`state`:

```js
// 1. Конфиг подключения (можно хранить в localStorage)
const ROS_URL = localStorage.getItem("ros_url") || "ws://localhost:9090";

// 2. Подключение
let ros = null;
function connectRos() {
  ros = new WebSocket(ROS_URL);
  ros.onopen = () => {
    subscribe("/odom", "nav_msgs/msg/Odometry", (msg) => {
      state.x = msg.pose.pose.position.x;
      state.y = msg.pose.pose.position.y;
      const q = msg.pose.pose.orientation;
      state.yaw = Math.atan2(
        2 * (q.w * q.z + q.x * q.y),
        1 - 2 * (q.y * q.y + q.z * q.z)
      );
    });
    subscribe("/battery_state", "sensor_msgs/msg/BatteryState", (msg) => {
      state.bat = msg.voltage;
      state.soc = msg.percentage * 100;
    });
    subscribe("/module_status", "rus_slam_interfaces/msg/ModuleStatus", (msg) => {
      const m = state.modules.find(x => x.id === msg.id);
      if (m) { m.steer = msg.steer_angle * 180 / Math.PI;
                m.rpm  = msg.drive_rpm;
                m.temp = msg.module_temperature;
                m.homed = msg.homed; }
    });
  };
  ros.onclose = () => setTimeout(connectRos, 2000);
}
function subscribe(topic, type, cb) {
  ros.send(JSON.stringify({ op: "subscribe", topic, type }));
  ros._subs = ros._subs || {};
  ros._subs[topic] = cb;
}
ros.addEventListener("message", (e) => {
  const m = JSON.parse(e.data);
  if (m.op === "publish" && ros._subs && ros._subs[m.topic]) {
    ros._subs[m.topic](m.msg);
  }
});

// 3. Публикация команд (в функции sim или в applyKeys)
function publishCmd() {
  if (!ros || ros.readyState !== 1) return;
  ros.send(JSON.stringify({
    op: "publish",
    topic: "/cmd_vel_nav",
    type: "geometry_msgs/msg/Twist",
    msg: { linear: { x: state.vx, y: state.vy, z: 0 },
           angular: { x: 0, y: 0, z: state.wz } }
  }));
}
```

**Отключение симулятора при наличии ROS-моста:** в начало функции
`sim(dt)` добавьте `if (ros && ros.readyState === 1) return;` —
тогда `state.x/y/yaw` будут приходить только из `/odom`.

> ⚠️ Эти правки **не входят** в исходный пульт автора. Они
> описаны как готовая «точка включения» — добавляйте их сами
> под свои требования к реальному стеку.

## 12. Известные особенности

* **Несколько вкладок одного пульта** в браузере делят
  `localStorage` — сохранённые маршруты синхронизируются
  через событие `storage`.
* **Глобальный `state`** — нет изоляции между экземплярами
  пульта (открытие двух окон приведёт к двум независимым
  симуляторам, но конфликтующим записям в `localStorage`).
* **Симулятор не считает** инерцию колёс, проскальзывание,
  трение — это идеализированная физика для демонстрации
  логики, не для валидации кинематики.
* **Карта сетки** фиксированного размера 320 × 240 и не
  сдвигается — при выезде за её границы (например,
  `|x| > 15.6`) включается «возврат в центр».

## 13. Диагностика

| Симптом | Причина | Решение |
| :--- | :--- | :--- |
| Карта пустая, робот не движется | Другой экземпляр пульта в той же вкладке | Перезагрузить страницу (`Ctrl+F5`) |
| Программа доставки не запускается | FSM в `FAULT` | Снять E-STOP, проверить модули |
| Колесо мыши не зумит карту | `file://` не передаёт `wheel`-events в preventDefault | Запустить через `python3 -m http.server` |
| Шрифты Inter/Manrope не подгружаются | Нет интернета | Не критично, fallback на system-ui |
| Сайдбар «съедает» контент | Узкое окно (< 1100 px) | Скрыть панель, развернуть окно |
